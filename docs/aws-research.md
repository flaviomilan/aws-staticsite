# AWS architecture research

Reviewed on 2026-10-06. The choices below distinguish AWS requirements from this kit's defaults. Provider 6.67.0 was resolved from the official Terraform registry during implementation; do not treat it as a permanent latest-version claim.

| Topic | Finding and decision | Primary source |
|---|---|---|
| Private origin | S3 REST endpoint, Block Public Access and OAC with always-on SigV4 signing. S3 website endpoints do not support OAC. | [AWS OAC](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/private-content-restricting-access-to-s3.html) |
| Certificates | Viewer ACM certificates must be in us-east-1, independently of the S3 region. DNS validation records must remain for managed renewal. | [CloudFront TLS requirements](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/cnames-and-https-requirements.html) |
| WAF | CloudFront WebACLs are global and managed through us-east-1. WAF is optional under this kit's pay-as-you-go baseline; start new managed rules in count mode. | [AWS WAF supported resources](https://docs.aws.amazon.com/waf/latest/developerguide/how-aws-waf-works-resources.html) |
| Routing | CloudFront Functions can rewrite paths and redirect hosts. Separate static directory routing from SPA navigation. Avoid blanket 403/404-to-200 fallback: that is an architectural choice to preserve asset errors. | [AWS Function examples](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/service_code_examples_cloudfront_functions_examples.html) |
| Cache | Response headers policies do not determine CloudFront's caching behavior. Use cache policies and S3 object Cache-Control metadata; min TTL zero respects revalidation. | [AWS response headers](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/modifying-response-headers.html) |
| Logs | Standard logging v2 supports S3, CloudWatch Logs and Firehose. Configure CloudFront log delivery through us-east-1; the S3 destination can be regional. The kit provides optional private S3 delivery with lifecycle retention. | [AWS logging v2](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/standard-logging.html) |
| WAF metrics | CloudFront WAF dimensions use WebACL metric name and Rule without a Region dimension. The kit uses a site-specific ACL metric name. | [AWS WAF metrics](https://docs.aws.amazon.com/waf/latest/developerguide/waf-metrics.html) |
| State | S3 supports native locking with use_lockfile. DynamoDB locking is deprecated; both mechanisms may coexist while clients migrate. Version the state bucket. | [HashiCorp S3 backend](https://developer.hashicorp.com/terraform/language/backend/s3) |
| CI identity | Use temporary credentials through GitHub OIDC. Limit audience and subject to the intended repository, branch and protected environment. | [AWS IAM OIDC](https://docs.aws.amazon.com/IAM/latest/UserGuide/id_roles_create_for-idp_oidc.html) |
| Pricing | CloudFront flat-rate plans bundle eligible services, but impose plan-specific restrictions on custom policies, logs and distribution features. This kit uses pay-as-you-go; fixed-price adoption needs a separate compatibility design. | [AWS flat-rate plans](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/flat-rate-pricing-plan.html) |
| Multi-tenant | CloudFront distribution tenants and managed certificates are relevant for a centralized SaaS. Independent distributions better fit this kit's isolation and migration requirements. Multi-tenant is deferred. | [AWS distribution options](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/distribution-config-options.html), [Managed certificates](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/managed-cloudfront-certificates.html) |
| Site generator | Astro supports static output deployed to S3/CloudFront. It is an example consumer; no framework-specific infrastructure is required. | [Astro AWS guide](https://docs.astro.build/en/guides/deploy/aws/) |

The original repository's universal sub-cent monthly estimate is not retained. Storage, requests, invalidations, zones, optional rules and observability depend on usage, account eligibility and current prices. See [costs](costs.md).
